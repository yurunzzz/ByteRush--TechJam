# Title: Autonomous Improvement of Long-View Ranking on KuaiRand-Pure

## Keywords
recommender systems, KuaiRand-Pure, within-user ranking, long-view prediction, GAUC, nDCG@5, factorization machines, autonomous machine learning research

## TL;DR
Develop and evaluate an autonomous machine learning research workflow that starts from the organizer-provided Factorization Machine baseline and improves within-user ranking of logged short-video impressions on KuaiRand-Pure. The system must use only the official training split for learning and public validation feedback for research decisions, maximize the official primary score defined as the equal-weighted mean of GAUC and nDCG@5, preserve the official evaluator and data split, avoid all test leakage and external training data, and produce a converged, reproducible, resource-aware result with complete experiment and recovery logs.

## Abstract
This project studies autonomous machine learning research for short-video recommendation using the required KuaiRand-Pure benchmark. The goal is not full-catalog retrieval: for each user, the model assigns a real-valued score to each video impression already present in the evaluation split, and the impressions are ranked from highest to lowest score within that user. The binary relevance label is the dataset's native `long_view` field, where `long_view=1` denotes a positive long-view event. Model quality is measured only with the organizer-provided evaluator using GAUC and nDCG@5, and the primary optimization objective is `primary = (GAUC + nDCG@5) / 2`. GAUC measures the overall within-user ordering of positive versus negative impressions and is computed only for users containing both classes, weighted according to the official implementation. nDCG@5 emphasizes placing positive impressions near the top five positions and follows the official zero-positive-user convention. The evaluation implementation in `evaluate.py` is authoritative and must not be modified or reimplemented with different conventions.

The official data split is chronological and fixed: training uses 2022-04-08 through 2022-04-21, validation uses 2022-04-22 through 2022-04-28, and the final test split uses 2022-04-29 through 2022-05-08. The research agent may train models and construct supervised features only from information legally available in the official training split. It may use public validation labels only after predictions have been produced, solely to evaluate experiments, choose configurations, select checkpoints, and determine convergence. It must never use validation labels as model inputs or feature-construction inputs. It must never access test labels, test metrics, or test-derived statistics during research and model selection. The final test set is reserved for one final submission generated from the validation-best checkpoint. All temporal aggregates and behavioral histories must be computed causally using only events earlier than the scored impression. Any feature whose timestamp provenance cannot be verified must be rejected. External training datasets are forbidden. Open-source software, published methods, and public papers may be used, but no external labeled examples may be joined to or used to train the recommendation model, and no pretrained weights trained on KuaiRand test labels may be used.

The root solution is the fixed organizer-provided NumPy Factorization Machine baseline. It uses five categorical fields: `user_id`, `video_id`, `author_id`, `tab`, and a training-derived video-duration bucket. Its reference validation performance is approximately GAUC 0.6674, nDCG@5 0.5357, and primary 0.6016. The first stage of every autonomous run must reproduce this reference within expected random-seed variation and must also verify the random and item-popularity sanity-check baselines before attempting improvements. The official data loader, chronological split, row order, evaluator, label definition, and submission schema are immutable experimental infrastructure. A candidate solution is invalid if it changes these components, evaluates on a different population, uses future information, writes predictions manually, or optimizes a locally redefined metric.

Training-split EDA and earlier validation runs are descriptive evidence, not an ordered method list. Each Stage 3 Agent receives the same verified incumbent, legal data capabilities, and validation-only feedback, then independently decides which single coherent hypothesis is most justified. The controller does not assign an algorithm family, research topic, donor, exploit role, or replacement direction.

Stage 3 uses five autonomous candidate slots. A candidate may choose any legal feature, model, objective, or training change that it can justify and implement under the trusted interfaces. Exact duplicates, implementation-equivalent changes, semantically near-identical hypotheses, and excessive concentration in one self-declared research family are rejected after generation; only the conflicting slot retries, using the conflict as feedback rather than receiving a prescribed alternative.

The autonomous experiment process must be staged and auditable. Stage 1 establishes a correct, runnable baseline and validates the evaluation and submission harness. Stage 2 tunes controlled hyperparameters on the same fixed task. Stage 3 performs the autonomous candidate search described above. Stage 4 performs ablations and replications to determine which components genuinely contribute. Each experimental node must state a testable hypothesis, identify its parent, record the exact code and configuration change, execute the relevant validation evaluation, store GAUC, nDCG@5 and primary, record runtime and compute use, save any checkpoint needed for reproduction, and distinguish engineering failures from scientifically valid negative results.

Node selection must be metric-driven and reproducible. A node is eligible only when it runs successfully, produces finite scores for every required row, preserves the official evaluator and split, passes leakage checks, and saves sufficient artifacts to reproduce its result. The main scalar for tree search is validation primary and higher is better. GAUC and nDCG@5 must always be recorded separately so that the agent can diagnose trade-offs and optionally maintain primary-best, GAUC-best, and nDCG@5-best candidates. Training loss or visual inspection must never override a worse official validation score. Promising improvements must be replicated across multiple random seeds and summarized with means and standard deviations before they replace the incumbent baseline. Since the published FM seed standard deviation is approximately 0.0008, very small single-run changes should not be treated as reliable improvements. The official convergence rule is epsilon 0.002 for three consecutive iterations: when three consecutive research iterations fail to improve validation primary by more than 0.002, or when the fixed compute or wall-clock budget is exhausted, the run is considered converged. The final model is the validation-best valid checkpoint observed by that point, not necessarily the last model trained.

Robustness and practical efficiency are first-class objectives. The agent should start with low-cost feasibility tests before launching full experiments; estimate runtime and memory needs; enforce per-node timeouts; reduce batch size after memory failures; lower learning rate or inspect inputs after numerical failures; retry transient API failures with bounded exponential backoff; and abandon a branch after a bounded debugging depth while preserving the best known valid checkpoint. Identical configurations should be detected and not rerun except for explicit replication seeds. Every run must report the number of human interventions, LLM input and output token usage, wall-clock duration, and GPU-hours. The agent should prefer improvements with a strong evidence-to-cost ratio rather than maximizing model size or exhaustively searching hyperparameters.

The final deliverable of the research loop is a reproducible recommendation model and checkpoint selected exclusively through validation, together with complete iteration logs and a prediction file in the organizer-required schema `row_id,user_id,video_id,score`. `row_id` must be zero-based and strictly increasing in the exact order returned by the official loader; `user_id` and `video_id` must match every evaluation row; `score` may be any finite real number because only within-user ordering matters. The final submission must pass the official `submit.py --check` validation before it is designated as final. Success means producing a converged, robust and reproducible validation result that improves on the official FM primary score while maintaining strict compliance with the fixed KuaiRand-Pure data, evaluator and hidden-test protocol.
